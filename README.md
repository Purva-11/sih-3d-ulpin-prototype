# BHOOMI-3D

**SIH 2026 Prototype — Problem Statement SIH26011**
*3D ULPIN Generation and Vertical Property Mapping System*

## Problem Statement
Conventional 2D cadastral representation becomes insufficient when properties exist vertically across multi-storey buildings, underground spaces, and other 3D structures. The problem statement demands an approach to horizontally and vertically index real estate into a 3D ULPIN ecosystem.

## Solution Overview
BHOOMI-3D is a prototype 3D cadastral intelligence platform. It represents land and property in both horizontal and vertical dimensions. The system connects land, buildings, floors, and properties in one spatial model, and implements a Spatial Intelligence Engine to detect spatial inconsistencies before they become downstream cadastral problems. 

## Technology Stack
- **Frontend**: React, TypeScript, Vite, Tailwind CSS
- **3D & Mapping**: Three.js / React Three Fiber, Mapbox GL JS
- **Backend**: Node.js, Express
- **Database**: PostgreSQL with PostGIS extension

## System Modules
1. **2D Cadastral Mapping**: Traditional parcel-level representation.
2. **3D Geographic Context**: Mapbox satellite/geographic context map.
3. **3D Locality Modelling**: Conceptual 3D representation of neighborhoods.
4. **Vertical Property Mapping**: Detailed 3D buildings mapped per floor and unit.
5. **Prototype 3D Property Identification**: Concept-generation of volumetric IDs indicating elevation and volume boundaries.
6. **AI/ML Processing Architecture**: Demo pipeline representing how automated floor segmentation and building extraction feed the database.
7. **Spatial Validation**: Live PostGIS-based topology and consistency checking.
8. **Human Review Workflow**: Pipeline for reviewing detected cadastral issues.
9. **Data Interoperability Architecture**: Structured approach indicating how authorized government APIs would populate this system.

## Database Architecture
The backend is powered by **PostgreSQL** coupled with the **PostGIS** extension for geospatial intelligence.
It stores spatial features (Parcels, Buildings, Floors, Properties) and their relationships, executing spatial queries for real-time rule validation (e.g. `ST_Contains`, `ST_Intersects`).

## Government Interoperability Architecture
BHOOMI-3D is designed for interoperability with authoritative cadastral and geospatial systems:
Government/State authoritative systems → Approved API / GIS service → BHOOMI-3D Integration Layer → Validation → PostGIS → 3D Cadastral Representation.

## Setup Instructions

### Environment Variables
Create a `.env.local` in the project root:
```env
VITE_MAPBOX_ACCESS_TOKEN=YOUR_MAPBOX_TOKEN
DATABASE_URL=postgres://user:password@localhost:5432/ulpin_postgis
PORT=5000
```
*(See `.env.example` for reference. Do NOT commit `.env.local` to source control.)*

### Database Setup
1. Ensure Docker is running.
2. Start the PostGIS container: `docker-compose up -d`
3. The database will be seeded automatically using the internal migration scripts (`server/db/run-migration.ts`) when the backend runs.

### Backend Setup
```bash
npm install
npm run dev:server
```

### Frontend Setup
```bash
npm run dev
```
The application will run on `http://localhost:5174`.

## Demo Workflow
1. Start at the **Integrated Dashboard** for a system overview.
2. Open **2D Cadastral** and select a land parcel.
3. Switch to **3D Satellite** or **3D Locality** to see contextual property layers.
4. Enter **Detailed Building** view, browse floors, and select a property.
5. Generate the **Prototype 3D Property ID** to view vertical volume.
6. Check **AI/ML Lab** for processing pipeline status.
7. Run **Spatial Validation** to trigger live PostGIS checks and review issues.

## Known Limitations
- Current dataset is prototype/demo data.
- Government/State authoritative database is not directly connected.
- Official ULPIN is not generated by this prototype (it uses a Prototype 3D Property ID).
- AI/ML models are simulated for presentation purposes.
- Production deployment requires authorized government data access, security, and interoperability standards.
